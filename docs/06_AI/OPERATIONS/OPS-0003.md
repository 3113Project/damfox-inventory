# OPS-0003

## Titolo

Ricostruzione storica retrospettiva di TASK-0001–TASK-0007

## Stato

Planned

## Obiettivo

Ricostruire, esclusivamente per completezza cronologica, i documenti mancanti relativi a `TASK-0001`–`TASK-0007` e le corrispondenti review retrospettive, usando soltanto informazioni verificabili dalla cronologia Git e dalla documentazione esistente.

I task ricostruiti devono risultare già completati e non devono mai essere considerati eseguibili dalla coda autonoma o dai comandi sintetici di Codex.

Questa è un'operazione documentale retrospettiva.

- cambiare lo stato operativo corrente del progetto;
- riaprire task già conclusi;
- inventare test, verifiche, date, commit o risultati non dimostrabili.

## Contenuto obbligatorio dei task

Ogni `TASK-000X.md` deve dichiarare chiaramente:

- `Stato: Completed`;
- `Tipo: Ricostruzione storica retrospettiva`;
- `Documento originale: non disponibile`;
- che il file è stato creato dopo il completamento dell'attività;
- che non costituisce autorizzazione a rieseguire il task;
- le fonti documentali o i commit effettivamente consultati;
- il risultato storico dimostrabile;
- eventuali dettagli non ricostruibili, indicati esplicitamente come tali.

Inserire inoltre, in posizione evidente:

> **Archivio non eseguibile:** questo task è già completato e deve essere ignorato da qualsiasi coda autonoma, comando `Esegui l'ultimo task` o selezione di task pianificati.

## Contenuto obbligatorio delle review

Ogni `REVIEW-000X.md` deve dichiarare:

- `Tipo: Review retrospettiva`;
- `Documento originale: non disponibile`;
- `Verdetto: NON APPLICABILE — ricostruzione storica`;
- che non vengono attribuiti test o verifiche non documentati;
- quali risultati sono dimostrabili dalla cronologia;
- quali elementi non possono essere ricostruiti con certezza;
- che il task era già completato prima dell'introduzione del workflow delle Engineering Review.

## Protezione dalla riesecuzione futura

Codex deve verificare e, se necessario, aggiornare esclusivamente la documentazione del workflow affinché valgano in modo esplicito le seguenti regole:

1. Solo task con stato esatto `Planned` possono essere eseguiti.
2. I task `Completed`, `Superseded`, retrospettivi o marcati come archivio non eseguibile devono essere sempre ignorati.
3. La presenza fisica di un file `TASK-XXXX.md` non costituisce autorizzazione all'esecuzione.
4. Un comando esplicito `Esegui TASK-0001`–`Esegui TASK-0007` deve essere rifiutato riportando che il task è storico e già completato, salvo una nuova autorizzazione esplicita del maintainer registrata in un nuovo task o operation.

Se le regole esistenti già garantiscono integralmente questi punti, non modificarle; documentare la verifica nel report.
