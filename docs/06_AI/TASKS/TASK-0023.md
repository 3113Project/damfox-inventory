# TASK-0023

## Titolo

Codex Cloud pilot — Unità di misura base

## Epic

Milestone 0.5 — Magazzino / fondazione catalogo

## Priorità

Media

## Stato

Planned

## Obiettivo

Implementare un primo verticale completo per le unità di misura e verificare il workflow Codex Cloud su branch dedicata e pull request, senza modificare direttamente `main`.

## Contesto

Le regole BR-053 e BR-054 stabiliscono che ogni prodotto possiede un'unità di misura principale e che il magazzino usa una sola unità di riferimento. Questo task introduce l'anagrafica delle unità di misura e il collegamento facoltativo al prodotto; confezioni e conversioni restano fuori perimetro.

Codex deve applicare `WORKFLOWS/ENVIRONMENT_BOOTSTRAP.md`. In Codex Cloud l'assenza del remote shell `origin` è prevista: usare direttamente lo snapshot del workspace e non arrestarsi per questo motivo.

## Operazioni da eseguire

1. Applicare il bootstrap adatto all'ambiente e leggere Costituzione, workflow, `REVIEW-0022`, `BUSINESS_RULES.md`, `DATABASE.md` e i moduli VAT, Categories e Products.
2. Creare `UnitOfMeasure` con:
   - base comune con id e timestamp;
   - `code` obbligatorio, normalizzato, univoco case-insensitive, massimo 16 caratteri;
   - `name` obbligatorio, massimo 100 caratteri;
   - `symbol` facoltativo, massimo 16 caratteri;
   - `is_active` booleano, default `true`.
3. Creare migrazione Alembic lineare e reversibile.
4. Implementare schema, service e router CRUD:
   - `GET /unit-measures/`
   - `GET /unit-measures/{id}`
   - `POST /unit-measures/`
   - `PATCH /unit-measures/{id}`
   - `DELETE /unit-measures/{id}`
5. Usare 404, 409 e 422 deterministici, rollback transazionale e dependency DB canonica.
6. Collegare facoltativamente `Product.unit_of_measure_id` con FK restrittiva; i prodotti esistenti restano validi con valore nullo.
7. Vietare con HTTP 409 la cancellazione di un'unità referenziata.
8. Aggiungere test per CRUD, unicità, PATCH, collegamento prodotto, cancellazione protetta, rollback, OpenAPI e regressione.
9. Aggiornare la documentazione pertinente.
10. Creare `REVIEW-0023.md`.
11. Aggiornare `TASK_INDEX.md` e `AI_STATE.md` nella branch solo dopo test verdi.
12. Aprire una pull request verso `main`. Non fare merge automatico.

## Vincoli

- Non implementare confezioni, conversioni, giacenze, scorte, movimenti o prezzi.
- Non rendere obbligatoria l'unità sui prodotti esistenti.
- Non modificare auth o utenti.
- Non usare `Base.metadata.create_all()`.
- Non fare push diretto su `main` o force push.
- Non usare segreti o collegamenti al server DAMFOX.
- Non tentare di configurare manualmente `origin` in Codex Cloud.
- L'assenza di `origin` nella shell cloud non è una condizione di arresto.
