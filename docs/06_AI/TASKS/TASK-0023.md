# TASK-0023

## Titolo

Codex Cloud pilot — Unità di misura base

## Epic

Milestone 0.5 — Magazzino / fondazione catalogo

## Priorità

Media

## Stato

Planned

## Obiettivo

Implementare un primo verticale completo per le unità di misura e, contemporaneamente, verificare il workflow Codex Cloud su branch dedicato e pull request, senza modificare direttamente `main`.

## Contesto

Il catalogo prodotti è consolidato e il progetto dispone di test, migrazioni e ambiente Docker riproducibile. Le regole BR-053 e BR-054 stabiliscono che ogni prodotto possiede un'unità di misura principale e che il magazzino usa una sola unità di riferimento. Questo task introduce soltanto l'anagrafica delle unità di misura e il collegamento facoltativo al prodotto; confezioni e conversioni restano fuori perimetro.

Questo è un test controllato di Codex Cloud. Il risultato deve essere proposto tramite pull request e non pubblicato direttamente su `main`.

## Operazioni da eseguire

1. Leggere `AGENTS.md`, la Costituzione AI, i workflow, `REVIEW-0022`, `BUSINESS_RULES.md`, `DATABASE.md` e i moduli VAT, Categories e Products come riferimento.
2. Creare il modello `UnitOfMeasure` con almeno:
   - `id` e timestamp ereditati dalla base comune;
   - `code`, obbligatorio, normalizzato, univoco senza distinzione tra maiuscole/minuscole, massimo 16 caratteri;
   - `name`, obbligatorio, massimo 100 caratteri;
   - `symbol`, facoltativo, massimo 16 caratteri;
   - `is_active`, booleano, default `true`.
3. Creare una migrazione Alembic lineare, completa e reversibile.
4. Implementare schema, service e router CRUD coerenti con i moduli consolidati:
   - `GET /unit-measures/`
   - `GET /unit-measures/{id}`
   - `POST /unit-measures/`
   - `PATCH /unit-measures/{id}`
   - `DELETE /unit-measures/{id}`
5. Usare errori deterministici 404, 409 e 422, rollback transazionale e dependency DB canonica.
6. Collegare facoltativamente `Product.unit_of_measure_id` all'unità di misura, con FK restrittiva e risposta prodotto coerente. I prodotti esistenti devono restare validi con valore nullo.
7. Vietare l'eliminazione di un'unità referenziata da almeno un prodotto con HTTP 409.
8. Aggiungere test automatici per CRUD, normalizzazione/unicità del codice, PATCH, collegamento al prodotto, cancellazione protetta, rollback, OpenAPI e regressione completa.
9. Aggiornare la documentazione tecnica pertinente.
10. Creare `REVIEW-0023.md` completa.
11. Aggiornare `TASK_INDEX.md` e `AI_STATE.md` nella branch del task soltanto dopo test verdi.
12. Aprire una pull request verso `main`. Non fare merge automatico.

## Vincoli

- Non implementare confezioni, conversioni, giacenze, scorte, movimenti o prezzi.
- Non rendere obbligatoria l'unità di misura sui prodotti esistenti in questo task.
- Non modificare auth o utenti.
- Non usare `Base.metadata.create_all()`.
- Non fare push diretto su `main`.
- Non fare force push.
- Non usare segreti o collegamenti al database del server DAMFOX.
- Il task deve funzionare nell'ambiente isolato Codex Cloud usando esclusivamente repository, Docker Compose e configurazione di test disponibile.
