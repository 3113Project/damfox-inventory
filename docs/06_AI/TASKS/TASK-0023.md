# TASK-0023

## Titolo

Unità di misura base — esecuzione locale

## Stato

Planned

## Tranche

Catalogo operativo 1 — esecuzione locale VS Code/server, durata complessiva massima stimata 5 ore.

## Obiettivo

Implementare l’anagrafica delle unità di misura e il collegamento facoltativo ai prodotti usando l’ambiente reale Docker/PostgreSQL del server.

## Prerequisiti

- `TASK-0022` completato.
- `REVIEW-0022` con verdetto `APPROVATO`.
- Working tree protetto secondo `GIT_WORKFLOW.md`.

## Perimetro

1. Creare `UnitOfMeasure` con:
   - `id`, `created_at`, `updated_at` dalla base comune;
   - `code` obbligatorio, normalizzato, massimo 16 caratteri e univoco case-insensitive;
   - `name` obbligatorio, massimo 100 caratteri;
   - `symbol` facoltativo, massimo 16 caratteri;
   - `is_active` booleano, default `true`.
2. Creare una migrazione Alembic lineare e reversibile.
3. Implementare schemi, service e router CRUD:
   - `GET /unit-measures/`
   - `GET /unit-measures/{id}`
   - `POST /unit-measures/`
   - `PATCH /unit-measures/{id}`
   - `DELETE /unit-measures/{id}`
4. Collegare facoltativamente `Product.unit_of_measure_id` con FK `RESTRICT`; i prodotti esistenti devono restare validi con `NULL`.
5. Restituire errori deterministici 404, 409 e 422; garantire rollback transazionale.
6. Vietare la cancellazione di un’unità referenziata da prodotti con HTTP 409.
7. Aggiungere test CRUD, normalizzazione/unicità, PATCH, rollback, associazione Product, cancellazione protetta, OpenAPI e regressione completa.
8. Aggiornare documentazione tecnica, changelog, `TASK_INDEX.md`, `AI_STATE.md` e creare `REVIEW-0023.md`.

## Vincoli

- Esecuzione esclusivamente locale su VS Code/server.
- Non implementare confezioni, conversioni, giacenze, scorte, movimenti o prezzi.
- Non rendere ancora obbligatoria l’unità nei payload Product.
- Non usare `Base.metadata.create_all()`.
- Non modificare auth o utenti.
- Non usare force push.

## Test obbligatori

```bash
docker compose build backend
docker compose up -d db backend
docker compose run --rm backend alembic upgrade head
docker compose run --rm backend python -m unittest discover -s tests -v
docker compose run --rm backend alembic check
```

Eseguire inoltre downgrade alla revisione precedente e nuovo upgrade a `head` su database di sviluppo ricreabile.
