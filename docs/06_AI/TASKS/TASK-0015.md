# TASK-0015 — Consolidamento del modulo VAT

## Stato

Planned

## Priorità

Alta

## Obiettivo

Portare il modulo VAT a uno standard affidabile e riutilizzabile: validazioni coerenti, transazioni sicure, errori HTTP prevedibili, test automatici e documentazione aggiornata.

## Prerequisito

`REVIEWS/REVIEW-0014.md` autorizza il proseguimento e il consolidamento della baseline è pubblicato su `origin/main`.

## Operazioni

1. Integrare correttamente i file VAT locali esistenti senza includere modifiche Categories.
2. Validare `name` secondo il limite del modello e vietare stringhe vuote o composte da soli spazi.
3. Validare `rate` secondo `DECISION-0004`: intervallo inclusivo `0.00–100.00`, massimo due cifre decimali e nessun valore nullo nei campi obbligatori.
4. Applicare anche nel database un vincolo `CHECK` coerente con l'intervallo approvato.
5. Impedire `null` espliciti per campi database non nullable negli update.
6. Usare `PATCH` per aggiornamenti parziali.
7. Implementare rollback in ogni errore transazionale.
8. Tradurre duplicati e violazioni di integrità in risposte HTTP coerenti.
9. Introdurre eccezioni applicative minime e riutilizzabili solo se necessarie.
10. Aggiungere annotazioni di tipo e docstring conformi agli standard.
11. Aggiungere test automatici per CRUD, duplicati, null, limiti, valori `0.00` e `100.00`, valori fuori intervallo, precisione eccessiva, rollback, 404, PATCH e OpenAPI.
12. Eseguire i test nel container.
13. Aggiornare documentazione, roadmap, features e changelog.
14. Produrre `REVIEWS/REVIEW-0015.md` con verdetto e autorizzazione o blocco di TASK-0016.

## File autorizzati

File VAT in `backend/app/models`, `schemas`, `services`, `api/v1`; package `__init__.py` necessari; eccezioni applicative strettamente necessarie; test VAT; migrazione correttiva strettamente necessaria per il vincolo `CHECK`; documentazione correlata; `TASK_INDEX.md`; `REVIEW-0015.md`.

- Non inventare ulteriori regole fiscali oltre a quelle documentate.

## Criteri di completamento

- Test VAT tutti verdi.
- Transazioni con rollback verificato.
- Errori HTTP deterministici.
- PATCH coerente.
- `rate` validato tra `0.00` e `100.00` inclusi, con due decimali al massimo.
- Modello, schema, migrazione e OpenAPI allineati.
