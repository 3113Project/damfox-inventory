# TASK-0014 — Consolidamento della baseline database e applicativa

## Stato

Planned

## Priorità

Critica

## Obiettivo

Rendere Alembic l'unica fonte di verità dello schema, correggere le fondamenta SQLAlchemy e dimostrare che il progetto può partire da un database vuoto in modo ripetibile.

## Contesto obbligatorio

Leggere integralmente:

- `docs/06_AI/DECISIONS/DECISION-0001.md`
- `docs/06_AI/DECISIONS/DECISION-0002.md`

- `docs/06_AI/CODEX_WORKFLOW.md`
- `docs/06_AI/GIT_WORKFLOW.md`

## Perimetro

Consolidare esclusivamente le fondamenta comuni. Non implementare Categories e non ampliare VAT oltre quanto necessario alla baseline.

## Operazioni

1. Controllare `git status` e preservare tutte le modifiche locali non pertinenti.
2. Correggere `backend/app/database/base.py` usando una naming convention SQLAlchemy valida e deterministica.
3. Uniformare la registrazione dei modelli nella metadata tramite `app.models`.
4. Configurare Alembic affinché usi `DATABASE_URL` dalla configurazione applicativa, senza URL concorrenti hardcoded.
5. Rimuovere `Base.metadata.create_all()` dall'avvio dell'applicazione.
6. Sostituire le migrazioni iniziali incoerenti con una baseline pulita e lineare per le sole entità già approvate e realmente presenti nella baseline: `users` e `vat_rates`, inclusi `id`, `created_at`, `updated_at`, vincoli e downgrade coerenti.
7. Non includere ancora `categories` nella baseline di questo task.
8. Eliminare la duplicazione di `get_db`, mantenendo una sola implementazione canonica e aggiornando gli import necessari.
9. Correggere whitespace, import e newline esclusivamente nei file toccati.
10. Ricreare il database di sviluppo secondo DECISION-0001 usando Docker Compose.
11. Eseguire `alembic upgrade head` su database vuoto.
12. Verificare che un secondo `alembic upgrade head` sia idempotente.
13. Avviare il backend e verificare endpoint `/`, `/docs` e schema OpenAPI.
14. Verificare tramite ispezione database che lo schema corrisponda ai modelli inclusi.
15. Aggiornare `DATABASE.md`, `ARCHITECTURE.md`, `ROADMAP.md` e `CHANGELOG.md` con lo stato reale.
16. Produrre `REVIEWS/REVIEW-0014.md` con verdetto, test, problemi residui e autorizzazione o blocco di TASK-0015.

- Database vuoto creato unicamente con Alembic.
- Nessun `create_all()` nell'avvio.
- Naming convention valida.
- Un solo `get_db` canonico.
- Configurazione database unica.
- Migrazioni User e VAT coerenti con i modelli.
- Backend avviabile e OpenAPI disponibile.
- Nessuna modifica locale non autorizzata inclusa.
