# TASK-0012 — Archivio automatico delle risposte Codex nel repository

## Stato

Planned

## Obiettivo

Predisporre nel repository un archivio versionato delle risposte finali di Codex, così che ChatGPT e il maintainer possano leggerle direttamente da GitHub senza copiarle manualmente.

## Contesto

Codex lavora nel workspace remoto `/srv/docker/damfox-inventory` tramite VS Code Remote SSH. `CODEX_WORKFLOW.md` stabilisce che ogni risposta finale debba essere salvata integralmente in `docs/06_AI/RESPONSES/`, un file Markdown per risposta.

## File da creare

- `docs/06_AI/RESPONSES/README.md`
- il primo file di prova in `docs/06_AI/RESPONSES/`

## File da modificare

- `docs/06_AI/README.md`
- `docs/06_AI/TASK_INDEX.md`
- `docs/06_AI/TASKS/TASK-0012.md`

## Operazioni

1. Leggere integralmente:
   - `docs/06_AI/CODEX_WORKFLOW.md`;
   - `docs/06_AI/GIT_WORKFLOW.md`;
   - `docs/06_AI/README.md`;
   - `docs/06_AI/TASK_INDEX.md`.
2. Creare `docs/06_AI/RESPONSES/README.md` spiegando:
   - scopo dell'archivio;
   - convenzione dei nomi;
   - contenuto minimo obbligatorio;
   - distinzione fra report del task e modifiche applicative;
   - politica di conservazione: nessuna eliminazione automatica;
   - uso da parte di ChatGPT per la review.
3. Aggiornare `docs/06_AI/README.md` aggiungendo il collegamento a `RESPONSES/` e descrivendo il flusso:
   - Codex esegue il task;
   - prepara la risposta finale;
   - salva la risposta integrale in `RESPONSES/`;
   - crea un commit amministrativo dedicato;
   - esegue il push quando possibile in fast-forward;
   - ChatGPT legge il report da GitHub.
4. Aggiornare `TASK_INDEX.md` impostando TASK-0012 come `Completed`.
5. Aggiornare questo file impostando lo stato a `Completed` prima del commit.
6. Preparare il report finale completo del task.
7. Salvare lo stesso report, senza riassunti o omissioni, in:

   `docs/06_AI/RESPONSES/TASK-0012_YYYY-MM-DD_HHMMSS.md`

8. Il report deve contenere almeno:
   - identificativo e titolo;
   - data e ora;
   - HEAD iniziale;
   - file creati e modificati;
   - verifiche eseguite;
   - commit e push;
   - anomalie;
   - testo finale destinato al maintainer.
9. Non creare script Windows, Scheduled Task o cartelle esterne al repository.
10. Non modificare backend, Docker o file applicativi.

## Vincoli

- Un file Markdown distinto per ogni risposta finale.
- Nessun segreto nel repository.
- Nessuna eliminazione automatica dei report.
- Nessuna modifica a report precedenti, salvo correzione esplicitamente autorizzata.
- Non includere nel commit modifiche locali estranee.
- Non usare `git add .` o `git add -A`.
- Non usare pull, merge, rebase, reset o force push.

## Verifiche

Eseguire:

- `git status`;
- `git diff --check`;
- `git diff --cached --check`;
- `git diff --cached --stat`;
- `git show --stat --oneline HEAD`.

Verificare che il report archiviato e la risposta mostrata al maintainer siano identici.

## Criteri di completamento

- `docs/06_AI/RESPONSES/` è documentata e tracciata da Git.
- Esiste almeno un report reale archiviato.
- Ogni futura risposta Codex può essere letta da ChatGPT su GitHub.
- Non è stato creato alcun componente Windows o archivio esterno al repository.
- TASK-0012 risulta `Completed` nell'indice e nel file del task.

## Condizioni di arresto

Fermarsi se:

- il commit includerebbe file non autorizzati;
- la cronologia locale non consente un push fast-forward;
- la risposta archiviata differisce da quella destinata al maintainer;
- sarebbe necessario modificare backend o file estranei.
