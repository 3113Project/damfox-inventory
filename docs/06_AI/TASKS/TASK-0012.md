# TASK-0012 — Archivio automatico delle risposte Codex sul Desktop Windows

## Stato

Planned

## Obiettivo

Creare un sistema affidabile che salvi ogni report finale di Codex in un file Markdown separato sul server e lo sincronizzi automaticamente in una cartella del Desktop Windows del maintainer.

## Contesto

Codex lavora nel workspace remoto `/srv/docker/damfox-inventory` tramite VS Code Remote SSH. Il workflow obbliga Codex a salvare ogni risposta finale completa in `/home/casa/codex-responses/`.

L'estensione Codex non offre nel repository una funzione documentata per esportare automaticamente ogni messaggio della UI. Questo task implementa quindi un archivio operativo dei report finali prodotti da Codex.

## File da creare

- `tools/windows/sync-codex-responses.ps1`
- `tools/windows/install-codex-response-sync.ps1`
- `docs/01_Development/CODEX_RESPONSE_ARCHIVE.md`

## Operazioni

1. Creare `tools/windows/sync-codex-responses.ps1`.
2. Lo script deve:
   - creare `$env:USERPROFILE\Desktop\DAMFOX Codex Responses` se non esiste;
   - usare `scp` per copiare esclusivamente i file `.md` da `casa@10.10.10.41:/home/casa/codex-responses/`;
   - non eliminare file locali o remoti;
   - non sovrascrivere inutilmente file invariati;
   - registrare gli errori in `$env:LOCALAPPDATA\DAMFOX\codex-response-sync.log`;
   - terminare con codice diverso da zero in caso di errore reale.
3. Creare `tools/windows/install-codex-response-sync.ps1`.
4. Lo script di installazione deve:
   - verificare la disponibilità di `scp.exe`;
   - creare la cartella di destinazione;
   - creare una Scheduled Task Windows denominata `DAMFOX Codex Response Sync`;
   - eseguire lo script di sincronizzazione ogni minuto e all'accesso dell'utente;
   - usare il profilo dell'utente corrente;
   - non richiedere credenziali hardcoded;
   - mostrare istruzioni chiare se l'autenticazione SSH senza password non è disponibile.
5. Creare `docs/01_Development/CODEX_RESPONSE_ARCHIVE.md` con:
   - architettura del sistema;
   - percorso server;
   - percorso Desktop;
   - prerequisiti OpenSSH;
   - installazione;
   - verifica;
   - disinstallazione della Scheduled Task;
   - troubleshooting.
6. Verificare la sintassi PowerShell con il parser disponibile, se presente. Se PowerShell non è disponibile sul server, eseguire una revisione statica e dichiararlo.
7. Non eseguire l'installazione Windows dal server.
8. Non modificare backend o Docker.

## Vincoli

- Nessuna password, token o chiave privata nel repository.
- Nessuna cancellazione automatica.
- Nessuna sincronizzazione dal Desktop verso il server.
- Non usare strumenti esterni non presenti di default oltre a OpenSSH `scp` e Windows Task Scheduler.
- Non modificare file fuori dal perimetro indicato, eccetto `docs/06_AI/TASK_INDEX.md` per aggiornare lo stato del task.
